# Bundled fonts

All binaries are unmodified upstream TTF/OTF files. Internal names, glyphs and shaping tables are retained. `app/src/main/assets/bundled-fonts.json` records each SHA-256, license, family grouping, routing tags and exact cmap ranges for supplements. Provisioning verifies the hash; catalog loading verifies recorded coverage against the file. Downloads happen only during asset preparation. The Android app has no Internet permission.

## Five visible families

- **MiSans** keeps Xiaomi’s original `MiSansVF.ttf` (SHA-256 `0ddef90648998900175cfdca9a6f087a2544c182f130b0ad4f7e94a03a115e79`) as its primary. The official Global packs provide Latin, Arabic/UI, Devanagari, Gujarati, Gurmukhi, Khmer, Lao, Myanmar, Thai, Tibetan, Traditional Chinese and L3 uncommon Chinese entries. These are declared members of the MiSans library family, rather than separate library or picker entries. Genuine variable faces are preferred, with original Regular/Bold companions where needed. Sources are Xiaomi’s [official download page](https://hyperos.mi.com/font/en/download/) and its `https://hyperos.mi.com/font-download/MiSans_*.zip` links. ZIP member CRCs and font hashes are recorded in [global-families.json](global-families.json). The original MiSans license PDF and its extracted text accompany the application; generated modules include both when a MiSans asset is packaged.
- **Rubik** is the [Google Fonts upstream variable TTF](https://github.com/google/fonts/blob/main/ofl/rubik/Rubik%5Bwght%5D.ttf), SHA-256 `1b3a7437ba2af80e465e773ed60c5036d1ba6ace492d89046dbcf18fb31e4e88`, under SIL OFL 1.1. Its upstream `OS/2` weight and `fvar` default are both 300 (Light). Generated modern XML explicitly seeds weight/axis 400 while retaining runtime weight support. Legacy XML puts the 400 instance first, followed by the other range-clamped instances. The font file itself is unchanged.
- **Noto Sans** is the full upstream variable Sans primary from the pinned Noto repository, with its Sans script/CJK/symbol faces grouped inside the Noto Sans library family. Serif specialists from the legacy common pool are not added to this Sans family.
- **Noto Serif** retains the [Google Fonts variable primary](https://github.com/google/fonts/blob/main/ofl/notoserif/NotoSerif%5Bwdth%2Cwght%5D.ttf), SHA-256 `4d8e6761424656867019081a1a01336f3cb086982682698714054fc33f782713`. Noto Serif script-specific fonts and Noto Serif CJK SC Regular/Bold belong to the Noto Serif library family. They are displayed within the family editor, not as separate top-level choices.
- **Sarasa Fixed** retains unmodified SC Regular (400) and Bold (700) from [Sarasa Gothic 1.0.42](https://github.com/be5invis/Sarasa-Gothic/releases/tag/v1.0.42), under SIL OFL 1.1. Archive SHA-256: `e9246d9549e30d978fb046c9ea4506a9cb7c72d3e640f146e645b99f75098f79`; Regular: `eca2c4618d27c83059e80d34000c41a48e14e578904a733f318732cb6924c2f6`; Bold: `349a5527d091776b714b63003628b327c04c2fa1e7e8985781ce0c75e232f7c7`. These faces already supply Chinese, kana, hangul, Latin, Greek and Cyrillic among their 51,225 encoded characters. Other scripts use the remaining explicit combination entries and then the system fallback. Missing-script fallback does not acquire Sarasa’s visual design or guarantee monospace metrics. SC is the regional glyph design; this does not bundle every Sarasa regional/style variant.

There is no single universal Noto font; [Noto’s documentation](https://notofonts.github.io/noto-docs/website/use/) describes its separate script families. No preset promises complete Unicode, every regional glyph variant, emoji sequence or identical shaping in every app.

## Family expansion and coverage

Version 0.2 uses explicit, named font combinations. The first entry is the primary; subsequent entries form an ordered fallback chain, followed by the original system fallback. The same resolved chain drives preview and module generation. Each selected library family expands only to its declared weight/style and language members. A MiSans family selection includes MiSans Global members; selecting Noto Sans includes its Sans members. No unrelated family or alternate Serif design is silently added. Script members retain script-specific native routes rather than being copied to every language route. No combination is bundled or assigned on a fresh installation. Existing personal selections are migrated locally without copying a global fallback to every style.

The former automatic-pool engine remains for compatibility and regression fixtures, not as a default for the combination UI. Its coverage figures below describe the available asset pool and legacy automatic expansion, not the coverage of a newly created combination.

The common pool contains 167 Noto Regular faces, preferring Sans where available, plus specialized Serif/symbol/music faces where needed. It is pinned to [notofonts/notofonts.github.io commit 5c39130](https://github.com/notofonts/notofonts.github.io/tree/5c3913063bb189df4edc94b766584dfb4c04a187/fonts) and [Noto CJK commit f8d1575](https://github.com/notofonts/noto-cjk/tree/f8d157532fbfaeda587e826d4cd5b21a49186f7c). Supplemental Serif variable faces are preferred where upstream supplies them; otherwise actual Regular/Bold faces are grouped together. Fonts without an appropriate Serif counterpart use the common pool. Full OFL texts accompany the APK and generated modules.

In the legacy automatic-pool preparation report, exact union cmap coverage was 137,902 codepoints for MiSans, 79,916 for Noto Serif, 80,921 for Sarasa Fixed, and 79,889 for Rubik or Noto Sans. Each union includes characters from 162 Unicode script properties. Counts include the selected primary and automatic supplements; they describe encoded characters, not guaranteed shaping or font appearance. Those asset-pool counts and exact sources/hashes are recorded in [global-families.json](global-families.json); the original common-pool sources remain in [sarasa-coverage.json](sarasa-coverage.json).

The current catalog has 228 binary faces with five visible entries; weight and language faces are shown inside their owning family; both the main library and the combination picker display families only. Font assets total approximately 214 MiB before APK compression. Only referenced fonts are packaged into a generated module. `tools/prepare-sarasa.py` creates the shared pool; `tools/prepare-global-families.py` extends it with the pinned Serif and official MiSans Global sources. Both retain original binaries. Re-run them in that order.

Font downloads under `artifacts/` are disposable caches; normal Android builds use the bundled assets directly. The preparation scripts recreate their Noto/MiSans download caches when needed. Sarasa preparation reuses the hash-verified, unmodified Regular/Bold files already in `app/src/main/assets/fonts/sarasa/`. To replace those inputs, extract the official Sarasa 1.0.42 archive into `artifacts/sarasa/`; the same pinned hashes are required.

## Scope, combinations and Android limits

The bottom navigation has Library, Combinations and Apply. Library imports and edits font families. Multiple TTF/OTF files and ZIP archives are grouped using the embedded typographic family name (name ID 16, falling back to ID 1). Import stages and validates the whole batch before committing any file. A conflicting or malformed face rolls back the batch. Individual faces are bounded at 128 MiB, a batch at 384 MiB and 256 fonts; ZIP entry names never become destination paths. TTC/OTC collections remain unsupported. Imported families support local renaming, adding/removing faces, native preview and face-specific variable-axis editing; their stable identity survives removal of the original representative face. Built-in binaries remain intact. Combination details edit a name, ordered entries and live preview. Apply only selects saved combinations, either one combination with a scope or a separate combination for Sans, Serif, Mono, Google Sans/LOS `variable-*`, Casual, Cursive and other named families. An omitted style retains its existing configuration. Editing a reused combination changes every assignment that references it; no copy is made behind the user's back.

Each generated style uses its own `fallbackFor` target scopes. Ordered entries are inserted before corresponding native language/variant fallbacks, with an unqualified tail for characters not represented by an existing route. Language tags rank candidates rather than restricting a font's glyph repertoire: incidental Han characters in a Khitan font can still be selected outside Khitan text. See [ColorOS investigation](COLOROS.md) for native provenance checks and the reason unrelated automatic script pools are no longer silently added. Language members are expanded within their own chosen family position; a Sans family does not acquire Khitan Serif as an implicit design choice. Original emoji families remain unchanged.

The optimizer reads actual system cmaps (including TTC indices), reuses verified redundant coverage and replaces existing fallback slots only when every original glyph remains available. After each replacement the proof uses the current chain. Redundant original slots may be retired only for selected chains, with explicit original-face copies retained for every unselected system/product name. Already ordered injected families are reused before another original slot is allocated. Supplements already fully covered by their own primary or earlier matching family faces are omitted without losing characters. Unknown coverage cannot authorize replacement or retirement. Font files and shaping tables are never rewritten.

Generation and installation both enforce Minikin’s 254-family limit for every native fallback chain, including named primaries, the first system family, product customizations and scoped fallbacks. All selected coverage must survive optimization; no fonts are silently truncated. Oversized configurations fail before installation. Multiple modules share the same limit. The frozen original four-font fixture remains as a regression for the previous bootloop, while `StyleCompositionTest` checks the current five presets and a four-style composition on the connected device without installing a module or rebooting.
