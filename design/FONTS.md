# Bundled fonts

All binaries are unmodified upstream TTF/OTF files. Internal names, glyphs and shaping tables are retained. `app/src/main/assets/bundled-fonts.json` records each SHA-256, license, family grouping, routing tags and exact cmap ranges for supplements. Provisioning verifies the hash; catalog loading verifies recorded coverage against the file. Downloads happen only during asset preparation. The Android app has no Internet permission.

## Five visible families

- **MiSans** keeps Xiaomi’s original `MiSansVF.ttf` (SHA-256 `0ddef90648998900175cfdca9a6f087a2544c182f130b0ad4f7e94a03a115e79`) as its primary. The official Global packs add Latin, Arabic/UI, Devanagari, Gujarati, Gurmukhi, Khmer, Lao, Myanmar, Thai, Tibetan, Traditional Chinese and L3 uncommon Chinese characters. Genuine variable faces are preferred, with original Regular/Bold companions where needed. Sources are Xiaomi’s [official download page](https://hyperos.mi.com/font/en/download/) and its `https://hyperos.mi.com/font-download/MiSans_*.zip` links. ZIP member CRCs and font hashes are recorded in [global-families.json](global-families.json). The original MiSans license PDF and its extracted text accompany the application; generated modules include both when a MiSans asset is packaged.
- **Rubik** is the [Google Fonts upstream variable TTF](https://github.com/google/fonts/blob/main/ofl/rubik/Rubik%5Bwght%5D.ttf), SHA-256 `1b3a7437ba2af80e465e773ed60c5036d1ba6ace492d89046dbcf18fb31e4e88`, under SIL OFL 1.1. Its upstream `OS/2` weight and `fvar` default are both 300 (Light). Generated modern XML explicitly seeds weight/axis 400 while retaining runtime weight support. Legacy XML puts the 400 instance first, followed by the other range-clamped instances. The font file itself is unchanged.
- **Noto Sans** is the full upstream variable Sans primary from the pinned Noto repository, with the shared Noto script/CJK/symbol family pool supplying missing glyphs. It is independently selectable as a primary, style assignment or manual fallback.
- **Noto Serif** retains the [Google Fonts variable primary](https://github.com/google/fonts/blob/main/ofl/notoserif/NotoSerif%5Bwdth%2Cwght%5D.ttf), SHA-256 `4d8e6761424656867019081a1a01336f3cb086982682698714054fc33f782713`. Its automatic family now includes the available Noto Serif script-specific fonts and Noto Serif CJK SC Regular/Bold before the shared missing-glyph pool. A script’s Serif design is retained even when the device already has a Sans font covering the same characters. Scripts without a corresponding Serif design continue through specialized Noto or Sans fonts.
- **Sarasa Fixed** retains unmodified SC Regular (400) and Bold (700) from [Sarasa Gothic 1.0.42](https://github.com/be5invis/Sarasa-Gothic/releases/tag/v1.0.42), under SIL OFL 1.1. Archive SHA-256: `e9246d9549e30d978fb046c9ea4506a9cb7c72d3e640f146e645b99f75098f79`; Regular: `eca2c4618d27c83059e80d34000c41a48e14e578904a733f318732cb6924c2f6`; Bold: `349a5527d091776b714b63003628b327c04c2fa1e7e8985781ce0c75e232f7c7`. These faces already supply Chinese, kana, hangul, Latin, Greek and Cyrillic among their 51,225 encoded characters. The full shared Noto pool fills other scripts by default. Missing-script fallback does not acquire Sarasa’s visual design or guarantee monospace metrics. SC is the regional glyph design; this does not bundle every Sarasa regional/style variant.

There is no single universal Noto font; [Noto’s documentation](https://notofonts.github.io/noto-docs/website/use/) describes its separate script families. No preset promises complete Unicode, every regional glyph variant, emoji sequence or identical shaping in every app.

## Family expansion and coverage

Every built-in and arbitrary imported font has automatic fallback enabled by default. Order is primary glyphs, explicit script selections, matching family supplements, the shared Noto pool, and the original device fallback chain. Turning automatic fallback off omits automatic family supplements and the pool; explicit selections remain. Restoring defaults clears manual/universal selections and enables automatic fallback, preserving style assignments, primary, axes and scope. Matching family expansion works for primary and style choices. Manual script/universal choices select the chosen face and its weight companions.

The common pool contains 167 Noto Regular faces, preferring Sans where available, plus specialized Serif/symbol/music faces where needed. It is pinned to [notofonts/notofonts.github.io commit 5c39130](https://github.com/notofonts/notofonts.github.io/tree/5c3913063bb189df4edc94b766584dfb4c04a187/fonts) and [Noto CJK commit f8d1575](https://github.com/notofonts/noto-cjk/tree/f8d157532fbfaeda587e826d4cd5b21a49186f7c). Supplemental Serif variable faces are preferred where upstream supplies them; otherwise actual Regular/Bold faces are grouped together. Fonts without an appropriate Serif counterpart use the common pool. Full OFL texts accompany the APK and generated modules.

With automatic fallback enabled, exact union cmap coverage is 137,902 codepoints for MiSans, 79,916 for Noto Serif, 80,921 for Sarasa Fixed, and 79,889 for Rubik or Noto Sans. Each union includes characters from 162 Unicode script properties. Counts include the selected primary and automatic supplements; they describe encoded characters, not guaranteed shaping or font appearance. Current per-family counts and exact new sources/hashes are in [global-families.json](global-families.json); the original common-pool sources remain in [sarasa-coverage.json](sarasa-coverage.json).

The current catalog has 228 binary faces with five visible entries; companions and script dependencies are hidden. Font assets total approximately 214 MiB before APK compression. Only referenced fonts are packaged into a generated module. `tools/prepare-sarasa.py` creates the shared pool; `tools/prepare-global-families.py` extends it with the pinned Serif and official MiSans Global sources. Both retain original binaries. Re-run them in that order.

Font downloads under `artifacts/` are disposable caches; normal Android builds use the bundled assets directly. The preparation scripts recreate their Noto/MiSans download caches when needed. Sarasa preparation reuses the hash-verified, unmodified Regular/Bold files already in `app/src/main/assets/fonts/sarasa/`. To replace those inputs, extract the official Sarasa 1.0.42 archive into `artifacts/sarasa/`; the same pinned hashes are required.

## Scope, combinations and Android limits

Single-font mode supports all system families, category toggles and individual named families. Mixed mode independently assigns Sans, Serif, Mono, Google Sans/LOS `variable-*` families, Casual, Cursive and other named families. An omitted style uses the existing system configuration. Android aliases continue to point to their original named targets. The one-click action honors this configuration; it never expands a partial selection to global.

Preview selects a category and expands its matching family with the same rules as generation. Each generated style’s script, manual and universal fallbacks use its own `fallbackFor` target scopes. Multiple targets with the same primary share faces where valid. Each style’s fallback optimization proves coverage independently; selected Serif/MiSans designs are not discarded merely because another design covers the same characters. Original emoji families remain unchanged.

The optimizer reads actual system cmaps (including TTC indices), reuses verified redundant coverage and replaces existing fallback slots only when every original glyph remains available. After each replacement the proof uses the current chain. Redundant original slots may be retired only for selected chains, with explicit original-face copies retained for every unselected system/product name. Already ordered injected families are reused before another original slot is allocated. Supplements already fully covered by their own primary or earlier matching family faces are omitted without losing characters. Unknown coverage cannot authorize replacement or retirement. Font files and shaping tables are never rewritten.

Generation and installation both enforce Minikin’s 254-family limit for every native fallback chain, including named primaries, the first system family, product customizations and scoped fallbacks. All selected coverage must survive optimization; no fonts are silently truncated. Oversized configurations fail before installation. Multiple modules share the same limit. The frozen original four-font fixture remains as a regression for the previous bootloop, while `StyleCompositionTest` checks the current five presets and a four-style composition on the connected device without installing a module or rebooting.
