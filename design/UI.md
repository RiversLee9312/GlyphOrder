# UI decisions

Checked against official guidance on 2026-11-07.

- Navigation has three sibling destinations: Library, Combinations and Apply. The final structure uses the native Material navigation bar, matching Google's [three-to-five-destination pattern](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns). There is no nested tab row or horizontal paging between bottom destinations. The library and all font selectors show whole font families. The family editor owns member files, names, axes and native preview; multi-file/ZIP imports group embedded family names. The library imports/edits families; combination details own naming, primary/fallback order and preview. Apply selects existing combinations without editing them. Chinese navigation labels are 字体库 / 字体组合 / 应用; the execution button is 应用字体.
- The [Material 3 Expressive app-bar guidance](https://m3.material.io/components/app-bars/) recommends **medium flexible** and **large flexible** in place of the former medium and large variants. GlyphOrder uses Compose's [MediumFlexibleTopAppBar](https://developer.android.com/reference/kotlin/androidx/compose/material3/MediumFlexibleTopAppBar.composable), with its native title sizes, heights and scrolled colors. [exitUntilCollapsedScrollBehavior](https://developer.android.com/develop/ui/compose/components/app-bars) is connected through nested scroll: upward scrolling collapses the headline into the compact bar, and returning to the top expands it. Snap and fling behavior remain the component defaults under the expressive theme.
- [Material motion](https://m3.material.io/styles/motion/overview) is implemented through `MotionScheme.expressive()`. Page changes and item reordering use the scheme's spatial springs; opacity uses effects specs. No hardcoded duration/easing curve imitates the component animations. Compose uses the platform duration scale.
- Library cards show the family name, preview, built-in status and total file size. The unhelpful format-abbreviation line is omitted. Detailed file properties belong in face details; chain order, weight controls and actual failures remain visible where they affect a decision.
- Family details, combination details and Apply each provide an explicit entry to the full preview page. It retains the complete default text, editable text, language samples, weight and size controls. Only this page defaults to 20sp, slightly above the 16sp body size; card and inline preview sizes remain unchanged. Library samples follow the app language.
- [Android settings guidance](https://developer.android.com/design/ui/mobile/guides/patterns/settings) and [Apple's writing guidance](https://developer.apple.com/design/human-interface-guidelines/writing) inform concise labels and direct action text. Relevant device constraints appear at the point of application, with ColorOS-specific notices gated by the detected ROM. Permission-protected OEM pages are avoided; the public settings launch has fallback and localized failure feedback. Personal font choices remain in device preferences; an empty installation does not choose a font combination for the user.
- Icons follow [the asset provenance and preparation workflow](ASSETS.md): official Google Fonts Material Symbols first; GPT Image only if no suitable symbol exists. No hand-drawn replacement paths.
- Reordering has a long-press drag handle, an Up/Down/Remove menu and accessibility custom actions. Destructive deletion of a saved combination names the affected combination in a confirmation dialog.
- Font and combination pickers use `ModalBottomSheet` with `skipPartiallyExpanded = true`, the [official fully expanded entry behavior](https://developer.android.com/develop/ui/compose/components/bottom-sheets-partial). They skip the extra half-height stop. Their lazy lists use available height for long content and wrap shorter content; no fixed 600dp cap forces another expansion gesture. This is a choice for these selection tasks, not a claim that every modal sheet should open full height.

Device checks covered separate font/combination tabs, native live preview, creation/name persistence, adding fonts, long-press reordering, menu reordering and deletion of a temporary combination. The final personal catalog was compared with its backup; the user's explicit cleanup retains their sans and mono combinations and restores the removed serif assignment to system default. Expanded and collapsed app-bar states were inspected on the connected phone.
